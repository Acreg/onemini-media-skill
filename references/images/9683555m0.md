# Grok：图片生成、分层与区域编辑

> **Onemini 图片 API 参数参考。** API 地址：`https://api.onemini.top`。更新日期：2026-11-15。

## 调用前准备

先设置正式站 API Key（以下示例使用 Bash）：

```bash
export API_KEY="替换成正式站 API Key"
```

表格中“—”表示未公布枚举或上下限；“未声明”表示没有明确公布默认值。可选参数仍须满足对应模式的条件。

## Grok 的三类图片能力

1. 普通文生图 / 图生图：不传 `operation`；不同精确 ID 的比例、参考图数量、质量字段并不相同。
2. 分层：仅 `grok-imagine-2.0-ext` 使用 `operation:"segment"`。
3. 区域编辑：仅 `grok-imagine-2.0-ext` 使用 `operation:"region_edit"`，来源是本站可访问的已完成分层/区域编辑资产。

`grok-imagine-image` 与 `grok-imagine-image-quality` 明确禁止 `quality` 字段；模型名中的 quality 不是让请求再传质量参数。`grok-imagine-image-2.0` 文生图可用 `quality:low/medium`，但一旦提供 `image_urls` 就禁止 `quality`。

部分型号名称包含 `edit`，但本页统一使用图片生成入口；不要据此改成 `/v1/images/edits`。

| --- | --- | --- |

| `grok-imagine-1.5-edit-apimart` | 本文第 1 组参数 | `POST /v1/images/generations` |

| `grok-imagine-image` | 本文第 4 组参数 | `POST /v1/images/generations` |

## 响应与结果获取

提交接口为 `POST /v1/images/generations`。请求受理后返回 **HTTP 202**，任务号位于 `data.task_id`（也有 `data.id`）。任务号不是图片下载地址。

使用同一 API Key 调用 `GET /v1/media/tasks/{task_id}`；`data.status` 为 `succeeded` 后，普通图片的文件链接位于 `data.result.images[].url[]`。详细状态、轮询与停止流程见 [媒体任务查询、结果下载与请求停止](https://docs-api.onemini.top/9683548m0)。媒体任务号不使用 `/v1/images/tasks/{task_id}` 查询。

## 1. `grok-imagine-1.0-apimart` / `grok-imagine-1.0-edit-apimart` / `grok-imagine-1.5-edit-apimart`

本组 ID 共享下列字段结构与约束；`model` 应填写所选的完整 ID，不是任选版本后缀。

**grok-imagine-1.0-edit-apimart：** 模型名称中的 edit 不代表改用 `/v1/images/edits`；请使用本页的生成入口。

**grok-imagine-1.5-edit-apimart：** 本型号不沿用 grok-imagine-1.5-apimart 的专属 n/size/参考图上限。

| `model` | 字符串（string） | 必填 | 未声明 | 本节所选精确 model ID | 请求时原样填写本节列出的 ID；不同后缀是不同模型。 |
| `prompt` | 字符串（string） | 否（条件见下） | 未声明 | 最少字符 1 | 描述要生成的画面，或参考图需要如何修改。 生成提示词。 |

### 条件必填、互斥与结构规则

### 本组基础调用示例

```bash
curl --request POST \
  --url "https://api.onemini.top/v1/images/generations" \
  --header "Authorization: Bearer ${API_KEY}" \
  --header "Content-Type: application/json" \
  --data-raw '{

```

调用本组其他型号时，只需把示例 `model` 换成上面同组的精确 ID；不要改成文档标题或自行删除后缀。

## 3. `grok-imagine-2.0-ext`

本组 ID 共享下列字段结构与约束；`model` 应填写所选的完整 ID，不是任选版本后缀。

**grok-imagine-2.0-ext：** operation 仅列 segment/region_edit，没有 generate 枚举：普通生成必须省略 operation。segment 不能带 n/size/response_format/image_id；region_edit 必须 image_id+prompt，且至少一种选区非空，禁止 image_urls/size/aspect_ratio。更完整的来源与模式示例见本页后半部分。

- 根级必填：`model`。
- 当 必须提供 `operation`；`operation` 固定 `segment` 时，不得满足（至少满足一项：[必须提供 `image_id`] 或 [必须提供 `image_index`] 或 [必须提供 `billing_model_name`] 或 [必须提供 `n`] 或 [必须提供 `size`] 或 [必须提供 `response_format`]）；必须且只能满足一项：[必须提供 `source_task_id`；不得满足（至少满足一项：[必须提供 `image_urls`]）] 或 [必须提供 `image_urls`、`cache_only`；`cache_only` 固定 `true`；`image_urls` 最少元素 1；最多元素 1；不得满足（至少满足一项：[必须提供 `source_task_id`] 或 [必须提供 `cached_only`] 或 [必须提供 `refresh`]）]。
- 当 必须提供 `operation`；`operation` 固定 `region_edit` 时，必须提供 `image_id`、`prompt`；`n` 固定 `1`；不得满足（至少满足一项：[必须提供 `image_urls`] 或 [必须提供 `size`] 或 [必须提供 `aspect_ratio`] 或 [必须提供 `billing_model_name`]）；至少满足一项：[必须提供 `selection_regions`；`selection_regions` 最少元素 1] 或 [必须提供 `boxes`；`boxes` 最少元素 1] 或 [必须提供 `object_indices`；`object_indices` 最少元素 1]。
- 当 不得满足（必须提供 `operation`） 时，必须提供 `prompt`。

## Grok 2.0 Ext 分层与区域编辑流程

### 来源与资产标识

- 普通生成时省略 `operation`；不能填 `operation:"generate"`。
- `segment` 可从本站成功来源任务发起；或使用一张参考图片做 `cache_only:true` 的缓存查询，两条路径互斥。
- 来源任务受当前用户、API Key、分组/线路、模型和成功状态约束，不能用上游任务号代替。
- `region_edit` 使用成功分层或区域编辑结果中返回的公开 `image_id`；它不是可自行构造的供应商资产 ID。


### 从已有任务获取分层信息

先在 shell 中设置以下环境变量：

- `SOURCE_TASK_ID`：本站已有且本人当前 API Key 可访问的成功来源任务 ID。

```bash
curl --request POST \
  --url "https://api.onemini.top/v1/images/generations" \
  --header "Authorization: Bearer ${API_KEY}" \
  --header "Content-Type: application/json" \
  --data-binary @- <<JSON
{
  "model": "grok-imagine-2.0-ext",
  "operation": "segment",
  "source_task_id": "${SOURCE_TASK_ID}",
  "include_mask_rle": true
}
JSON
```


### 对单张图片仅查询分层缓存

先在 shell 中设置以下环境变量：

- `REFERENCE_IMAGE_URL`：自己可直接访问的参考图片地址。

```bash
curl --request POST \
  --url "https://api.onemini.top/v1/images/generations" \
  --header "Authorization: Bearer ${API_KEY}" \
  --header "Content-Type: application/json" \
  --data-binary @- <<JSON
{
  "model": "grok-imagine-2.0-ext",
  "operation": "segment",
  "image_urls": [
    "${REFERENCE_IMAGE_URL}"
  ],
  "cache_only": true,
  "include_mask_rle": true
}
JSON
```


### 使用公开图片资产做区域编辑

先在 shell 中设置以下环境变量：

- `GROK_IMAGE_ID`：本站成功分层/区域编辑结果中返回的公开 image_id。

```bash
curl --request POST \
  --url "https://api.onemini.top/v1/images/generations" \
  --header "Authorization: Bearer ${API_KEY}" \
  --header "Content-Type: application/json" \
  --data-binary @- <<JSON
{
  "model": "grok-imagine-2.0-ext",
  "operation": "region_edit",
  "image_id": "${GROK_IMAGE_ID}",
  "prompt": "将选中区域改成蓝色，保留其他部分",
  "n": 1,
  "selection_regions": [
    {
      "outer": [
        [
          0.1,
          0.1
        ],
        [
          0.7,
          0.1
        ],
        [
          0.7,
          0.7
        ],
        [
          0.1,
          0.7
        ]
      ]
    }
  ]
}
JSON
```

### 特殊响应与结果

仍从提交回执的 `data.task_id` 查询媒体任务。分层结果可能包含 `image_id`、`image_url`、`objects` 与蒙版信息；普通生图则使用 `images[].url[]`。缓存查询可能出现 `cache_status:"miss"`，此时没有可继续编辑的资产，不能把缓存未命中当作已完成分层。

区域编辑结果可在 `images[].items[].image_id`、`images[].image_ids[]` 或直接的 `image_id` 位置提供公开资产引用，字段是否存在以实际结果为准。保留服务返回的值用于下一次 `region_edit`，不要推导或复制私有资产编号。
